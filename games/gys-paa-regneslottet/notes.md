### Program Manager fix

The bundled `PROGMAN.INI` references `Group3=C:\WINDOWS\NETVÆRK.GRP`, but the game does not need the Windows network group. Because encoding/mojibake mismatches can trigger a Windows 3.x "Fejl i gruppefilen" prompt, `launch.sh` removes Group3 from `PROGMAN.INI`, removes `3` from `Order=...`, and deletes stale `NETV’RK.GRP` / `NETVÆRK.GRP` files in the private runtime tree.

### Audio debugging

Initial validation reached the game but the user reported that the sound stuttered badly. A first attempt with PipeWire-style tuning (`rate=48000`, `blocksize=2048`, high prebuffer, dynamic/30000 cycles) still sounded wrong to the user.

User then supplied YouTube reference:

```text
https://www.youtube.com/watch?v=S4dxcR1phqU
```

Reference audio sample downloaded for inspection with `yt-dlp` via `uvx`; the sampled stream is AAC LC, 44100 Hz, stereo, 128 kb/s.

The original bundled DOSBox-SVN/Daum config also uses:

```text
machine=svga_et4000
memsize=512
core=auto
cputype=486
cycles=auto
rate=44100
blocksize=1024
prebuffer=20
sbtype=sb16
```

DOSBox-Staging 0.82.2 rejected `cpu_cycles=auto` and fell back to 3000, causing the Windows program to quit quickly. `memsize=512` also produced large-memory warnings and was not needed. The final repo launcher keeps stable Staging-compatible timing while matching the reference audio path:

```text
SDL_AUDIODRIVER=pulse
machine=svga_et4000
memsize=16
core=auto
cputype=486
cpu_cycles=40000
rate=44100
blocksize=1024
prebuffer=20
mididevice=none
voodoo=false
ne2000=false
```

Final smoke log confirms:

```text
SDL: version 2.32.70 initialised (wayland video and pulseaudio audio)
MIXER: Initialised stereo 44100 Hz audio with 1024 sample frame buffer
CDAUDIO: Operating at 44100 Hz without resampling
DISPLAY: SVGA 640x480 256-colour graphics mode 2Eh
```

Human listening confirmation is still required; the agent cannot reliably judge audio quality from logs alone.
